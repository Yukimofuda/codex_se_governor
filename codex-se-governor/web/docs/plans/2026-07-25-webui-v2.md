# WebUI Version 2 Implementation Plan

> **For Claude:** Use `${SUPERPOWERS_SKILLS_ROOT}/skills/collaboration/executing-plans/SKILL.md` to implement this plan task-by-task.

**Goal:** Upgrade Codex SE Governor from an early local-first prototype into a polished, accessible, responsive governance workspace while preserving safe static analysis and explicit evidence boundaries.

**Architecture:** Keep the existing vinext/Sites application and IndexedDB storage. Split the monolithic client into reusable shell, workspace, editor, inspection, AI, and export modules. Browser code owns local projects, uploaded files, static checks, and BYOK AI requests; the Sites Worker exposes only declared safe capabilities unless a separately secured backend resource is available.

**Tech Stack:** React 19, TypeScript, vinext, Sites Worker runtime, IndexedDB, Web Crypto, CodeMirror 6, Lucide React, Node test runner.

---

## Requirements

- Preserve every current working feature and the no-user-code-execution boundary.
- Replace the ambiguous `Local-first` status card with an interactive Security & Privacy Center.
- Add grouped collapsible navigation, command palette, engineering topbar, density settings, system-aware themes, Chinese/English/bilingual modes, reduced motion, and high-contrast support.
- Redesign Dashboard, project/task wizards, artifacts, Prompt Builder, repository checks, validation, metrics, releases, history, settings, help, and methodology.
- Keep all displayed results grounded in the active project. `UNKNOWN`, `NOT RUN`, and user attestations never count as `PASS`.
- Add session-only BYOK AI support with optional encrypted local storage. Every proposed AI change requires review before applying.
- Support ZIP, directory listing, local folder selection, and public GitHub repository inspection without executing repository content.
- Support Markdown, ZIP, Prompt, JSON/CSV metrics, printable PDF report, release manifest, and SHA-256 export evidence.
- Provide PWA metadata and offline-safe local workflows.
- Treat account sync, private repositories, service-side AI proxying, comments, and team collaboration as unavailable until real backend resources are configured.

## User Story

As a software project owner, I want one polished workspace to create lifecycle artifacts, inspect governance evidence, review AI suggestions, and export reproducible packages so that I can use the Governor without a terminal while understanding exactly what was and was not verified.

## Acceptance Criteria

- AC-001: Navigation groups collapse independently and the full sidebar collapses to icon mode.
- AC-002: `Cmd/Ctrl+K` opens a keyboard-accessible command palette.
- AC-003: Appearance supports system/light/dark, comfortable/compact density, reduced motion, and high contrast.
- AC-004: Language supports Chinese, English, and bilingual labels with browser-language default.
- AC-005: Dashboard uses active project data and has onboarding when no project exists.
- AC-006: Project and task wizards validate required fields, save drafts, show review summaries, and use task-specific prompts.
- AC-007: Artifact workspace provides file navigation, source/preview/structured views, outline, checks, traceability, revisions, and export.
- AC-008: AI keys are not included in IndexedDB project records, logs, ZIPs, reports, or rendered output.
- AC-009: Repository checks never run uploaded code and reject unsafe archive paths and generated artifacts.
- AC-010: Validation distinguishes PASS, FAIL, WARNING, NOT RUN, UNKNOWN, browser static, service, and user evidence.
- AC-011: Exports use UTF-8-safe names and exclude local paths, secrets, caches, and macOS artifacts.
- AC-012: Mobile, tablet, desktop, and wide layouts remain usable without overlap.
- AC-013: WCAG 2.2 AA-oriented keyboard, focus, labels, contrast, reduced motion, and touch targets are present.
- AC-014: Build, type checks, lint, unit tests, server-render tests, and browser checks pass before deployment.

## Design Decisions

- Information density: mixed default with comfortable/compact switch.
- Navigation: grouped collapsible sidebar plus command palette.
- Topbar: breadcrumbs, context, save state, validation state, readiness, search, and `+` menu.
- Palette: separate light/dark systems with restrained black-purple-gold gradients and deep-blue action color.
- Typography: Apple system stack and PingFang where available; Geist Mono for engineering data.
- Surfaces: flat workspace sections, repeated-entity cards, 6-8px work surfaces, 12px overlays, restrained glass.
- Icons: SF Symbols-like Lucide icons plus a responsive Governor Gate geometric mark.
- Dashboard: project/readiness header, lifecycle, real metrics, risks, tasks, activity, and customizable preset views.
- Motion: richer onboarding/dashboard/methodology motion; restrained editor/table motion; system reduced-motion support.
- Background: glass/grid navigation, clean work areas, spotlight only on narrative/empty states.
- Editor: CodeMirror source view, preview, structured views, outline, field checks, traceability, revisions, and AI review.
- Repository check: ZIP, folder, tree text, and public GitHub URL; static analysis only.
- Validation: overview, lifecycle board, filterable findings, evidence details, and comparison-ready history.
- Metrics: Executive, Engineering, Security, and Release presets with source and confidence.
- Security center: data location, AI provider, upload, sharing, execution boundary, and destructive data controls.
- Responsive: dedicated mobile navigation and touch workflows; wide-screen multi-panel tools.
- Sharing/account capabilities: hidden or explicitly unavailable unless real authentication and durable storage are configured.

## Data Model

- `WorkspaceProject`: project context, tasks, preferences, layout presets, activity, validation snapshots.
- `TaskPackage`: task input, artifacts, revisions, checks, links, generated timestamps.
- `ArtifactRevision`: artifact, content, source, timestamp, label.
- `ValidationSnapshot`: status groups, findings, evidence provenance, timestamp.
- `UserPreferences`: theme, language, density, motion, contrast, sidebar state, dashboard preset.
- `AIProfile`: provider metadata and model; API key remains in memory or separately encrypted browser storage.

## Security Model

- Browser-static archive parsing with size, count, path, UTF-8, symlink, and compression checks.
- No `eval`, dynamic script execution, Markdown HTML execution, repository tests, package scripts, or binaries.
- GitHub import requests only public metadata and text; no credentials in URLs or downloads.
- AI requests disclose destination and send only user-selected context.
- File names are normalized before download. Secret and absolute-path checks run before export.
- Cloud/auth UI remains absent unless secure resources and deletion controls are implemented.

## Risks

| Risk | Probability | Impact | Mitigation | Contingency |
|---|---:|---:|---|---|
| Large UI scope introduces regressions | Medium | High | Modular components, pure functions, regression tests | Roll back to current Sites version |
| CodeMirror/icon dependencies increase bundle | Medium | Medium | Lazy load editor, tree-shake icons | Retain enhanced textarea fallback |
| Provider CORS blocks direct BYOK | Medium | Medium | Connection test and explicit unsupported result | Disable provider until secure proxy exists |
| Browser storage quota is exceeded | Medium | Medium | Storage meter, revision limits, export | Prompt user to export and remove old history |
| Glass/animation harms performance | Medium | Medium | Limit blur layers, reduced motion, mobile simplification | Disable costly effects by capability query |
| Cloud features lack secure resources | High | High | Hide or label unavailable, no fake actions | Ship local-safe product and stage backend separately |

## Rollback

- Keep implementation on `codex/webui-v2`.
- Do not alter the currently deployed Sites version until all checks pass.
- Save a new Sites version from one validated commit.
- If production verification fails, redeploy the previous saved version and retain exported local project compatibility.
